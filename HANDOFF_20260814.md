## The rule that did most of the work

> **Ratio ~1 gets a label fix. Ratio ~0.001 gets a weighing. Anything in between
> is a real question and stays open.**

Take a recipe line's quantity, multiply by the ingredient's own per-pack rate, and
compare with what the book actually charges:

    Broccolini  0.22  x $3.17/bunch = $0.6974   book $0.6945   ratio 0.996
    Lettuce     0.083 x $2.75/ea    = $0.2283   book $0.2283   ratio 1.000
    Shallot     900   x $3.30/bunch = $2970     book $10.16    ratio 0.0034

Ratio 1.0 means the number is **already being read as packs** and only the word is
wrong — so `data/recipe_line_unit_fixes.yaml` gets an entry with **no
`cost_factor`**, which the file always supported and which had never been used.
Ratio 0.001 means the line genuinely is in grams and needs a bunch weight off a set
of scales. Relabelling those would turn 900 g of shallots into 900 BUNCHES.

# 2. The audit's warnings — where the rest of the money was

`audit_book` reports SEVERE / WARN / INFO and only SEVERE fails CI, so the 129
WARNs had never been worked. Four classes were fixable.

## The one that mattered: a product with no cost could never be given one

**The loop that never terminated, and every step in it was individually correct.**

The bridge turns a supplier invoice into a ProductID's cost by converting the
price into that ProductID's own unit. It takes that unit from `seed_conv`, which
is built from the product's EXISTING seed. So:

> a product with no cost has no seed → no conversion → the bridge emits nothing →
> it still has no cost.

Adding a `product_map` row for one of these did **precisely nothing**, which is
why "line contributes $0 despite a real quantity" had sat at 16 for weeks. What
it was costing:

    22962978 White Pepper   4 recipes seasoning for free (10, 10, 10, 7.5 g)
    22962975 bicarb         2 marinations at 50 g each — the velveting agent
    22874517 Yuzu Juice     Shiba Highball, 10 ml, and HALF the drink's cost

Back Office states `Unit` for all three — g, g, ml. Only `CostPriceIncTax` was
missing. **The basis was never unknown; it was not being read from the one file
that had it.** `bo_declared_units()` reads it.

The rule is deliberately the narrowest one that works: it applies **only when the
invoice is already in the unit Back Office declares**, so there is no divisor, no
scale factor and nothing inferred. The reason for that narrowness is specific —
the magnitude guard protecting every other bridged row compares against the
product's SEED PRICE, and a product with no seed has none, so that guard cannot
fire here. A rule that needed arithmetic would be *unguarded* arithmetic.

Measured, not assumed: exactly **3** identities gained a cost and **0** existing
rates moved more than 20%. Shiba Highball went $0.75 → $1.47.

## $999 of spirits, and one of them was a spelling

Hendricks, Campari, Bacardi and Italicus had been bought since June and none was
in the cost book. "Pack unreadable" is true of the description and false of the
line — ILG state the pack in their own UOM (`6x700ML` → 0.700 L) and `cogs_list`
had been carrying it all along.

`seed_matched_liquor_cost` exists for exactly this: form the case reading and the
bottle reading, keep whichever agrees with the product's seed, refuse both if
neither does. **It fires only for a bridged product.** These four had no bridge,
so the rescue never ran. The fix is the bridge; the rescue then judged, and
refused every case reading:

    Hendricks  $0.0896/ml vs seed $0.1069   (case 0.14x, refused)
    Campari    $0.0619/ml vs seed $0.0515   (case 0.20x, refused)
    Bacardi    $0.0715/ml vs seed $0.0716   — 0.999x
    Italicus   $0.0951/ml vs seed $0.0930

**Campari was also a spelling bug.** `product_map` already had it — as ILG
`395-102-1`, the *pricebook* spelling — while every invoice writes `395-1021`.
`_ilg_key()`'s own docstring says ILG writes one code two ways, and `load_bridge`
keys on the literal string, so that row had never matched an invoice in its life.
It is the **only one of 77** ILG map codes affected (checked), so it is fixed by
adding the invoice spelling rather than normalising every key and moving 76
bridges that already work.
