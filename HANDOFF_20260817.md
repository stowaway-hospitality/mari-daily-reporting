## Why this was possible (the root cause)

`scripts/ingest_insights_email.py`:

```python
def target_date(msg):
    dt = parsedate_to_datetime(msg.get("Date"))   # the EMAIL's send time
```

**The date comes from when the email arrived, not from the report.** The product
export contains no date column at all, so a report re-sent on the 10th is filed
as the 10th. One re-send with two attachments corrupted HG and Mari on the same
two Mondays.

**The fix that ends this class**, and it is a Lightspeed settings change, not
code: add **`Sale Closed Date`** to the scheduled product report (the hourly
report already has it). `export_guards.assert_export_is_for()` is already wired
in and will enforce it the moment the column appears — it stays silent until
then because it cannot invent a date it was never given.

Do this on both companies: Insights → Reports → Product sales → the schedules.

## What shipped yesterday (all tested, all on main)

`scripts/export_guards.py` + `scripts/test_export_guards.py` (16 checks, in CI):

- **duplicate refusal** — an export byte-identical to another date's is rejected
  before a number is computed, naming the file it duplicates

  such rather than as a blank; HG's nine closed Tue/Sun all deliver this file

  `Position/Product Number/Sale Amount`; the second is normalised and logged

- **`reconcile_against_till`** — warns on divergence >10%; tolerance measured,
  not guessed (product sits 1–3% under hourly every day, from voids/open price)

`scripts/health_monitor.py` + `scripts/test_missing_sales_check.py`:

- the missing-sales check now examines **yesterday** (it started at 2 days back,
  so the day most likely to be wrong was never looked at)
- "does this weekday trade" now reads the full history CSV, not the ~6-week
  window of per-day JSON files
- **wages decide a closed day**: no sales + no wages = shut; no sales + a real
  shift = a genuine gap. HG's shut Sunday shows $0; its shut Tuesday shows $83
  of cleaning, so the bar is a shift's worth
